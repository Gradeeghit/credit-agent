# 检索质量评测说明（C5）

> 用途：解释**检索相关的数字怎么来的、怎么读、能得出什么结论、不能得出什么结论**。
> 与其它文档的关系：需求口径看 `docs/需求规格说明书-codebuddy-deepseek-v4.1flash.md`；
> 做到哪一步看 `docs/任务进度.md`；本文只讲"评测怎么算"。
> 最后更新：2026-11-03 ／ 最近一次数据：三档同表（含 rerank），双语料

---

## 1. 一句话结论

制度检索的三条路里：**VECTOR（向量）稳态最好，+RERANK（专用重排）在 3 份办法的语料上提升 +8.54%（已过 PRD 的 5%），HYBRID（等权 RRF 融合）反而拖后腿**。
所以主链路（`DomainBriefAssembler` 的制度域前置检索）保持 **VECTOR**；是否给制度域加 rerank 待拍板（数据已足够，见 §5、§6）。

---

## 2. 评测在测什么

**只测"该召回的那段条文有没有被找出来"，不测"模型回答对不对"。**

两样东西是固定资产，随代码进版本库，才能复现：

| 资产 | 说明 | 位置 |
|---|---|---|
| 语料 | 条文切片，每片有 `chunkId` | `rag/src/test/resources/eval/c5-corpus.json`（虚构 30 段）、`c5-real-corpus.json`（真实 3 份办法 170 片） |
| 标注 query | 每条问题标了标准答案切片 `gold` | `c5-queries.json`（65 条）、`c5-real-queries.json`（92 条） |

流程：query → 检索器 → 前 3 条 → 与 `gold` 比对 → 算分。

---

## 3. 指标定义

| 指标 | 算法 | 怎么读 |
|---|---|---|
| **Recall@k** | 前 k 条命中 `gold` 的条数 ÷ 总条数 | "3 条里有没有那条" |
| **MRR** | 每条取 `1/名次`（第1名=1、第2名=0.5、第3名=0.333、未命中=0），再平均 | "命中的靠不靠前"，恒 ≤ Recall@k |
| **相对提升** | （新 − 基线）÷ 基线 | 例：(1.0000 − 0.9692) / 0.9692 = **+3.17%** |
| **名次变化条数** | 有多少条 query 的前 3 顺序被改变 | 为 **0** 说明重排**没生效**（降级或模型名不对），该行数据不可用 |

**逐条示例**（虚构语料，VECTOR）：

- `Q18 晚还一天会有什么后果`，`gold=10`（逾期处理条），召回前 3 是 `[22, 11, 28]` → **未命中**
- `Q62 一个月工资两万 最多能借多少`，`gold=4`（额度测算条），前 3 是 `[13, 6, 2]` → **未命中**
- 其余 63 条命中 → Recall@3 = **63/65 = 0.9692**

## 4. 字面档 / 改写档

65 条与 92 条标注都按**问法风格**打了两档标签（`tag` 字段）：

| 档 | `tag` | 定义 | 例子 |
|---|---|---|---|
| 字面档 | `literal` | 问法直接搬用条文术语 | `用于个人消费的贷款期限不得超过五年` |
| 改写档 | `paraphrase` | 同一个问题用大白话问，几乎不含原文术语 | `消费贷最多能贷几年`、`晚还一天会有什么后果`、`被拒了以后能不能给个说法` |

**为什么要分档**：两档考的能力不同。

- 字面档 ≈ 关键词匹配，BM25 就能满分；
- 改写档 ≈ 语义理解，条文写"逾期之日起按合同利率上浮50%计收罚息"，用户问"晚还一天会有什么后果"，**一个字都不重合**，BM25 直接 0 召回。

分档后才知道平均分是被谁拖下来的——真实语料上 BM25 总体 0.6935，但字面 0.9677、改写只有 0.4194。

## 5. 实测结果（2026-11-03）

环境：embedding/rerank 均走 maas 端点（`qwen3.7-text-embedding-flash` + `qwen3.7-text-rerank`），候选宽 20，k=3。

### 5.1 虚构语料（30 段 / 65 条，31 字面 + 34 改写）

| 档位 | Recall@3 | MRR | 字面 | 改写 |
|---|---|---|---|---|
| VECTOR | 0.9692（63/65） | 0.9538 | 1.0000 | 0.9412 |
| BM25 | 0.9231（60/65） | 0.8872 | 1.0000 | 0.8529 |
| HYBRID（RRF k=60） | 0.9538（62/65） | 0.9231 | 1.0000 | 0.9118 |
| **VECTOR+RERANK** | **1.0000（65/65）** | **0.9846** | 1.0000 | **1.0000** |

rerank：改变 top3 **58/65**，相对 VECTOR **+3.17%**，MRR +0.0308（救回的 2 条均排第 1）。

### 5.2 真实条文语料（3 份办法，170 片 / 92 条，46 字面 + 46 改写）

| 档位 | Recall@3 | MRR | 字面 | 改写 |
|---|---|---|---|---|
| VECTOR | 0.8913（82/92） | 0.7572 | 0.9348 | 0.8478 |
| BM25 | 0.7283（67/92） | 0.6322 | 0.9783 | 0.4348 |
| HYBRID（RRF k=60） | 0.8261（76/92） | 0.7101 | 0.9783 | 0.6739 |
| **VECTOR+RERANK** | **0.9674（89/92）** | **0.8460** | 0.9783 | **0.9565** |

rerank：改变 top3 **78/92**，相对 VECTOR **+8.54%**，MRR +0.0888（改写档 0.8478 → 0.9565）。

> **语料难度决定结论**：2 份办法（62 条）时 rerank 只有 +3.39%（因为基线已 0.9516，上限只剩 3.39%）；
> 加到 3 份办法（92 条，多了《流动资金贷款管理办法》51 条 + 附件公式）后，VECTOR 基线掉到 0.8913，
> 上限打开到 `10/82 = +12.2%`，rerank 提升随之变成 **+8.54%** —— 这才超过 PRD 的 5%。

## 6. 三个可以直接用的结论

1. **制度域保持 VECTOR，不切 HYBRID**：三套语料上 HYBRID 都低于 VECTOR（虚构 −1.5pp、真实 2 份 −9.7pp、真实 3 份 −6.5pp），因为等权 RRF 会把 BM25 的错项带进前三。
2. **rerank 是唯一稳定加分的一档**：虚构 +3.17%、真实 2 份 +3.39%、真实 3 份 **+8.54%**，且改写档提升最明显（0.8478 → 0.9565）。
3. **PRD 的 "≥5%" 取决于语料难度，不是实现**：虚构语料基线 63/65，上限只有 3.17%，无论怎么优化都到不了 5%；3 份办法的语料上限 12.2%，rerank 拿到 **8.54%** 才越过 5%。**结论：要判断 C4 是否达标，必须用足够难的卷子**。

  "-Dsurefire.excludedGroups=noop" "-Dsurefire.failIfNoSpecifiedTests=false"

## 8. 踩过的坑（按代价排序）

| # | 坑 | 现象 | 处理 |
|---|---|---|---|
| 1 | **rerank 模型名填错** | 接口可能仍 200，但分数没区分度 → 名次不动 → 看起来"开了没收益"（曾误判为 +0.00%） | 模型名必须是该端点 `/v1/models` 里真实存在的（这里是 `qwen3.7-text-rerank`，不是 `qwen3-rerank`）；跑完先看"名次变化条数"是否 > 0 |
| 2 | **rerank 端点拼错** | 404，误以为"端点不支持" | `DashScopeReranker.resolveEndpoint` 会把 `/compatible-mode` 剥掉再拼 `/compatible-api/v1/reranks`；探测时不要带 `/compatible-mode` |
| 3 | **降级被当成有效结果** | 全部调用失败 → 降级回原顺序 → Recall 与基线完全相同 | `C5ModesLiveTest` 在 `名次变化==0` 时打印"该行不可用"；不要只看分数 |
| 4 | **断言写在评测之前** | `changed` 只在执行检索函数时累加，提前判断永远为 0 → 用例莫名跳过 | 先评测、后断言 |
| 5 | **`-Dtest` 作用到上游模块** | 报 `No tests matching pattern` 直接 BUILD FAILURE | 加 `-Dsurefire.failIfNoSpecifiedTests=false`（用 `-am` 时必须带） |
| 6 | **PowerShell 吃掉 `-D` 里的点** | `Unknown lifecycle phase ".xxx"` | 整段加引号：`"-Dsurefire.excludedGroups=noop"` |

## 9. 不能从这个评测得出的结论

1. **不能说明"回答正确率"**：召回对了 ≠ 结论对、引用对。要测这个得做人工标注的端到端验收。
2. **样本仍不算大**：65 条下单条 = 1.54pp、92 条下 = 1.09pp；"±1 条"仍能改变小数点后一位。
3. **真实语料是"按条切分"**，线上是"按章节 + 800 字滑窗"切分；同一条文可能被切碎或跨块，分数不能直接等价。
4. **只覆盖 3 份贷款办法**：个人贷、固贷、流贷；未覆盖征信业务、互联网贷款等。
5. **虚构语料是自造的**，措辞比真实政策规整，难度偏低（BM25 在它上面也能到 0.92），所以**只看虚构语料会低估 rerank 的价值**（+3.17% vs 真实 3 份 +8.54%）。
